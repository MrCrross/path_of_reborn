## 1. Команда ролей и ответственность

Работай в следующих ролях. Если среда поддерживает агентов, можно разделить непересекающиеся задачи; это необязательное условие. Один интегратор отвечает за итог, общие файлы и тесты.

2. **Senior Godot Gameplay Engineer** — CombatResolver, авторитетное состояние GameSession, автоматические атаки, обработка отказов, события для presentation.
3. **RPG Systems & Save Engineer** — награды за попытку, отдельно первичные мета-награды, XP и маршрут в данных, миграции, Checkpoint, отсутствие дюпов/потерь.
4. **Narrative Interaction Designer** — безопасный Skip линейного пролога, обязательные команды, resume и осмысленные выборы.
5. **Technical Artist / UI / Game Feel Designer** — интеграция полноразмерных текстур через ArtMap, импорт, масштаб, anchors, анимационная совместимость, прозрачная победа, сцена, иконки, телеграф, обратная связь, safe area, pause/back, отделение света сцены от подложек UI.

## 4. Целевое взаимодействие

`Путь → одно «Идти дальше» → появление врага → автоматические базовые атаки → победа/добыча без подтверждения → Путь`.

В бою остаётся осмысленное ручное уклонение. По умолчанию автоатака включена. Это рабочее решение по запросу пользователя: **не** автоматическое уклонение и **не** автоматический запуск следующего боя. При необходимости сохранить ручной режим, спрячь его выбор в компактные настройки, без дополнительной большой кнопки на боевой сцене. Не показывай одновременно бессмысленные дубли «Атака», «Авто» и «Дальше».

Постоянный HUD: только HP у актёров, понятный сигнал опасности, доступное уклонение и компактная пауза. Путь: одно главное действие и небольшая навигация. Уровень/XP/подробности — в профиле, название места кратко при входе; доступный выбор роста отмечается тихим бейджем, не модальным требованием.

## 5. Сначала исправь состояние и награды

В `GameSession.apply_victory` сейчас смешаны две задачи: защита повторного callback и запрет награды за любой следующий бой с тем же enemy_id. Поэтому после слизи и гоблина рост останавливается. Не исправляй это удалением всех проверок.

Сделай минимальный явный контракт попытки боя:

- У каждой действительно новой встречи есть стабильный `encounter_run_id` или эквивалентный ID попытки. enemy_id обозначает тип врага; route_node_id — узел продвижения. Эти понятия не взаимозаменяемы.
- GameSession является единственным владельцем settlement: получает terminal event CombatResolver, применяет состояние ровно один раз независимо от существования CombatScreen. UI только отображает результат.
- Новый выигранный run даёт обычные XP и loot. Повторный finished/settle того же run ничего не добавляет. Два отдельных боя с одним enemy_id могут дать два обычных пакета награды.
- Первичное Эхо, сюжетное открытие, техника и другая разовая мета-награда остаются разовыми по предусмотренному ID. Повтор и Checkpoint не дублируют мета-награды.
- Обычные XP, инвентарь, деньги и маршрут откатываются вместе с профилем Checkpoint. Мета сохраняется по прежним правилам. Ledger/ID попыток и RNG должны иметь явно описанную политику при rollback; не оставлять вечный запрещающий ledger вне откатываемого профиля.
- Сохраняй только согласованное состояние. Нельзя сохранить inventory.changed посередине выдачи, пока run ещё не отмечен завершённым: это создаёт дюп после загрузки. Используй небольшую границу mutation/batch и одно итоговое событие, а не новый общий transaction framework.
- В UI больше не должно быть `session.apply_victory(...)`. Исход боя, XP и предметы доступны уже к моменту показа «Победа».

Награда автоматически поступает в сумку. Автоматической экипировки нет. Уведомление содержит реальные item_id/instance_id, количество, необязательный просмотр/сравнение и действие «Надеть». Не теряй доступ к вещи после исчезновения уведомления. Если выпало несколько вещей в один слот, не надевай все по порядку под одной кнопкой; выбор предмета должен быть конкретным.

Старый pending_reward не терять: перед следующим encounter и при Continue/миграции должен существовать один идемпотентный путь его доставки. Сейчас `route_for_continue` его игнорирует, а следующая первая победа заменяет массив. Воспроизведи случай регрессией, затем исправь. Уже начисленный в старом профиле XP не начислять второй раз при доставке старого pending loot.

Расширяешь DTO — повышай schema_version, добавь чистую миграцию старой версии, default/validation и round-trip; обработай старые Checkpoint snapshots. Миграция не должна требовать удаления профиля. Произвольный таймер UI не является границей фиксации наград. При ошибке сохранения показывай честный статус и не дублируй попытку выдачи при повторе записи.

## 6. Автоатака и время боя

Автоатака живёт в доменной симуляции/маленькой политике над текущим CombatResolver, а не в Timer экрана или кнопочном callback. Урон проходит одним путём, с теми же правилами защиты, cooldown, уязвимости и terminal lock. Если ручная атака остаётся для режима, она использует этот же механизм и не даёт второй удар в тот же tick.

Нужны наблюдаемые события начала/контакта атаки и исхода, чтобы код presentation не выводил состояние по таймеру на глаз. Не начисляй урон сразу, если визуальный замах только начался и контакт должен быть позже. Выбери и документируй минимальную timing-модель; не строй систему способностей ради одной базовой атаки. Смерть до контакта отменяет оставшийся удар; terminal event испускается один раз. Определи детерминированный порядок одновременных контактов и сохрани его в тесте.

Автоатаки и атаки врага остановлены при intro, result, pause, background и потере активного приложения. После возврата нет burst/catch-up за время отсутствия. После смерти не остаются живые timers/tweens, способные ударить или повторно выдать награду. Вступление завершается одним способом; resize/удаление сцены не запускает бой дважды.

Не оставляй текущий баланс без измерений: сейчас auto-hero убивает слизь двумя ударами за ~0.4 с до её первой атаки. Рабочая гипотеза для настройки: обычная встреча **4–8 с**, читаемый telegraph и хотя бы одна реальная возможность уклониться. Это ориентир теста, не обязательное время каждого боя. Настрой в данных HP/cadence/окна, проверь героя без экипировки и с доступной экипировкой, уровни и Следы. Не повышай врагам урон просто ради длительности. Повышение характеристик должно ощущаться, но не убирать весь контент одним кадром.

В `start_combat` сейчас есть полное лечение героя. Сохрани эту семантику в данной итерации и зафиксируй её в документе; изменение модели лечения требует отдельного обоснования и баланса. Не подменять UX-задачу скрытым расходом зелий/HP.

## 7. Победа и поражение без промежуточных остановок

Удали ResultPanel/ContinueButton как обязательный шаг победы. Покажи крупную **«Победа»** золотым/жёлтым текстом, без панели, заливки и полноэкранного затемнения. Добавь тонкую тёмную обводку/тень для чтения на небе/листве. Прототип на текущей базе 180×320: размер 22–26 logical px, вся sequence 0.9–1.2 с; проверь ширину и композицию, вынеси значения в одно место. Не закрывай головы и HP. Плавность — alpha и короткое движение с округлением; не размывай пиксельный мир масштабированием.

Враг показывает ясное поражение и уходит из сцены, его HP скрывается. Используй существующий hit/fade как временный вариант до отдельного death asset. Hero остаётся в живой сцене, а не за тёмным окном. Добыча/XP уже применены доменом; presentation можно прервать без потери награды.

Затем верни Путь автоматически. Никаких «К пути», «Продолжить», «Забрать» и «ОК». Уведомление о добыче не захватывает обязательный фокус. Выбор улучшения и предложения надеть предмет доступны, но их разрешено отложить. После победы нет автоматической следующей встречи.

На поражении: короткая реакция и автоматический переход непосредственно к существующему выбору Checkpoint. Убрать кнопку «Выбрать возврат». **Сам возврат не автоматизировать**: показать цену, откат, сгорающие точки, последствия 3/3; исполнить только после решения игрока. Не вводить бесплатный retry.

Защити смену экранов от click-through: press/hold, начатый на боевой кнопке, release, повтор клавиши и эмулированная мышь не должны подтвердить новую экранную команду. Для нового шага нужен новый жест после готовности экрана. Повторное открытие/закрытие уведомления не повторяет settlement.

## 8. Пропуск катсцены

Добавь в пролог одну компактную явную кнопку «Пропустить» в safe area с полноценной зоной касания. Для первого запуска смысл важнее экономии трёх букв. Не использовать один неизвестный значок без accessible name. Без окна «Вы уверены?»; нажатие на Skip не должно перелистнуть реплику под ним.

Это не `router.go_to("world")` и не быстрый цикл из 44 taps. Нужна идемпотентная операция завершения текущей линейной последовательности:

- Остановить hold/swipe/transition/flash и события презентации.
- Выполнить необходимые пропускаемые story-команды по whitelist/постусловиям ровно один раз; нынешние команды set_world_flag/set_npc_flag сверить с JSON.
- Одинаковое обязательное состояние после нормального завершения и Skip: доступ в World и необходимые флаги. Не начислять XP/loot или будущие покупки за пропуск.
- Записать исход sequence как completed/skipped; не приравнивать «пропущено» к «игрок прочитал». Интегрировать с действующей Once/seen и Continue-политикой без повторного запуска на каждом load/Checkpoint.
- Применить state batch и сохранить на безопасной границе до ухода; не сохранять десятки частичных команд по пути. Не писать SaveService из виджета.
- При Skip из line/look/hold/transition, двойном тапе и немедленном quit/relaunch получить один переход и целый профиль.
- Будущие диалоги с выборами нельзя пропускать с автоматическим выбором ветки. Skip останавливается перед значимым выбором. Не вводи сами ветвящиеся диалоги без задачи.

Сохрани полноценное чтение пролога, пагинацию, отмену раннего hold и отсутствие двойного ввода. Возможность перечитать сюжет можно добавить через существующий доступный путь; не строй большую галерею воспоминаний для этой задачи.

## 9. Рост и честное продвижение

Различай level героя, route node и вид врага. В старом runtime два enemy definitions, первая цепочка даёт уровни 1→2→3; XP-таблица допускает 4. Не называй это «тремя локациями».

Техническая цель этой итерации: убрать тупик, а не имитировать полную главу. Вынеси простую последовательность доступных encounter nodes и параметры повторов в Resources/JSON. UI берёт следующий узел из состояния, не проверяет `slime_beaten/goblin_beaten` для определения всего маршрута. Успешный основной бой продвигает соответствующий узел один раз; повтор не продвигает сюжет.

На существующих двух типах сделай короткий воспроизводимый маршрут технического slice с данными сложности, без выдуманных сюжетных открытий. Его состав и параметры отметь как prototype. После последнего доступного узла честно показать «Участок пройден» и доступный повтор; не оставлять «Идти дальше», которое тайно снова запускает первую слизь. Не рисуй неработающие кнопки следующих глав.

Рост поддерживает narrative-ориентир **до уровня 5**, достижимый обычным текущим циклом и повторами. Начальная гипотеза XP-порогов: `[4, 8, 12, 18]`, именно стоимость следующего уровня, не cumulative totals. Сохрани данные отдельно от UI и проверь pacing; при лучшей обоснованной таблице запиши причину. У cap показывай понятное состояние, не XP «до следующего» с нулевым знаменателем. Доступные выборы улучшений не теряются при отложенном выборе, переходе и загрузке.

Не выдавай технический рост до 5 за реализацию всей narrative-главы. Роща, Синий Овраг и Костяной дозорный требуют реальных encounters/story/abilities; состав следующего контентного этапа перечисли отдельно. Не создавать 100 уровней, ежедневки, энергию, рекламу, онлайн или бесконечную экономику.

## 12. Обязательная приёмка

Нужны реальные регрессии:

1. Бой без атакующих taps: герой автоматически наносит урон; враг отвечает; ручное уклонение работает в окне. Не доказывать auto-attack вызовом `request_attack()` внутри самого теста.
2. Auto и ручная атака в один tick не удваивают урон; cooldown соблюдён; один terminal event. Tick batching даёт тот же результат при одинаковом input schedule.

6. Legacy save v1 с pending reward → load → доставка → save → reload → следующий бой: ничего не потеряно и не выдано повторно. Воспроизвести существующий defect до исправления.
7. Checkpoint после новых правил откатывает обычную прогрессию/loot и сохраняет meta; ID/ledger/RNG и новые route fields проходят round-trip и rollback.

10. Поражение открывает выбор возврата без промежуточного вопроса; ни один платный возврат не выполняется сам.
