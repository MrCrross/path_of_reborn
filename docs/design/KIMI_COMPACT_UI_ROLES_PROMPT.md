# Kimi Code — компактный мобильный UI, роли и критерии

Скопировать текст после разделителя в Kimi Code, открытый в корне `path_of_reborn`. Это продолжение рефакторинга от 20 ноября, а не повтор исходного задания от 19 ноября.

---

Ты работаешь над Path of Reborn, Godot 4.7.x / GDScript / Compatibility, mobile portrait pixel-art RPG. Выполни дальнейшую доработку UI и магазина в репозитории, сохраняя работающую игру. Пользователю не нравится, что интерфейс занимает слишком много места, кнопки большие, а текстовые пояснения повторяются. Он прямо предложил иконки, например Iconify.

## 2. Работай с явными ролями

Исполняй следующие роли последовательно; если среда поддерживает агентов, можно выделить независимые задачи. Не считай, что роль обязана быть отдельной моделью. Назначь одного интегратора. Параллельные исполнители не редактируют один и тот же файл.

| Роль | Ответственность | Обязательный результат |
|---|---|---|
| **Lead Mobile UX Designer / интегратор** | Приоритет информации, thumb zones, экранные бюджеты, маршруты, борьба с дублями | Набор wireframes и краткая таблица «видно всегда / по событию / по запросу». Решения подкреплены кадром и замером |
| **Pixel UI Art Director** | Палитра, типографика, масса иконок, рамки, портреты и фоны | Конкретные visual tokens и список недостающих assets; единая сетка, без случайных наборов иконок |
| **Senior Godot UI Engineer** | Control/Container-композиция, тема, безопасные зоны, ввод, фокус, состояние экранов | Рабочие сцены и скрипты без дублирующего роутера/Theme/DialogueRunner |
| **Narrative UX / Interaction Designer** | Диалоги, жесты, постановка, ритм чтения | Сохранены 44 cue, parts, Once и команды; персонажи не дублируются; действие понятно без повторного абзаца |
| **Gameplay Economy Engineer** | Кошелёк, торговые данные/команды, save/load, Checkpoint rollback | Атомарная покупка/продажа и изолированный от UI владелец денег; цены в данных |
| **Independent Mobile QA** | Реальные сценарии, touch/Back/фокус, размеры, ошибки и регрессии | Воспроизводимые проверки и PNG из runtime; отдельный список фактически не проверенного |

Lead определяет минимальное связное изменение. Art Director не меняет доменные правила. UI Engineer не придумывает валюту и баланс. Economy Engineer не перестраивает визуальные сцены без контракта. QA проверяет результат независимо от заявления автора «готово».

## 3. Направление дизайна

Игровая сцена — главный фокус. У интерфейса один основной акцент, спокойные тёмные подложки и тёплый текст. Меньше рамок и подписей; не уменьшай шрифт, чтобы вместить прежний объём объяснений.

Повторяемые действия — **иконки**. В проекте уже есть `UiIcons` и локальные SVG Pixelarticons 2.4.2: меч, уклонение, рюкзак, назад, закрытие, информация, карта и др. Используй каталог, не подключай JS/CDN/WebView и не загружай весь Iconify в игру. Лицензию и происхождение сохраняй. Новые символы бери из того же набора или готовь оригинальную пиксельную руну с карточкой источника.

Разделяй видимый glyph и touch area. Текущая гипотеза: иконка 24 logical px, обычная кнопка 32×32, бой 40×40. Можно визуально облегчить поверхность/рамку, сохранив зону касания. Проверяй Android 48×48 **dp**, не выдавай 48 desktop px за dp.

Текст остаётся там, где принимает решение: имя говорящего, название/цена выбранного товара, недостаток денег, подтверждение необратимой продажи/возврата. Не превращай все действия в загадочные glyph-only кнопки. Названия действий для accessibility обязательны; tooltip не заменяет touch-обучение.

Не показывать постоянно: «тапните», клавиши Space/E/I/C, внутренние ID, номера cue/ticks, описание всех правил Checkpoint, объяснение предназначения материалов, подпись следующей встречи вместе с тем же названием в цели. Debug — только `--debug-ui`.

## 4. Экраны и задачи

### Combat

- Сохрани полноценную сцену за HUD. Не возвращай вертикальный стек «enemy panel → маленькая arena → hero panel → hints → result placeholder → большие кнопки».
- HP врага наверху, HP героя компактно; атака/уклонение в зоне большого пальца. Протестируй обе кнопки без подписи на новом игроке. Если смысл уклонения не считывается, одноразово поясни его рядом с целью, а не на каждом боевом тике.
- Угроза и окно ответа — у противника. Цвет дополняется символом/формой; cooldown читается без меняющегося текста на кнопке.
- Damage numbers остаются у цели; Arena должна быть Control, иначе Container переставит Label. Не добавляй Label эффектов напрямую в раскладывающий Container.
- Сохрани один telegraph tween на фазу. В тиках только симуляция и непрерывные индикаторы; текст/перестройка UI по событиям.
- Не меняй CombatResolver, тайминги, урон, награды и количество ударов ради демонстрации UI.

### Dialogue / cutscene

- Сохрани одну нижнюю карточку, имя и до 3 измеренных строк. Высота по содержимому, без пустого этажа под кнопки.
- Пагинация использует фактический Font/ширину через DialoguePaginator. Не возвращай один лимит символов для всех экранов. При resize не теряются слова и позиция чтения.
- Касание текста и свободной сцены перелистывает ровно один раз, включая эмулированную мышь после touch. Look — только hotspot/жест; hold отменяется при раннем отпускании и завершается однократно. Нельзя проскочить cue на release после hold.
- Жестовые cue показывают один компактный сигнал; не возвращай длинную инструкцию плюс такую же подпись на кнопке.
- Foreground-портреты подготовь отдельно по арт-пайплайну. Непрозрачный фон 180×320 нельзя растягивать как прозрачный портрет. При отсутствии cutout зафиксируй art gap и используй существующую полноценную сцену.
- Сохрани канонический JSON, порядок, IDs, parts, Once, commands и resume. Не внедряй Skip/Auto/History без полного рабочего поведения.

### World, Title, Inventory, Reward, Checkpoint

- World: свободный центр, компактный герой/HP, короткая текущая встреча с действием, существующие Сумка/Печать. Показывать только действующие ограничения; не добавлять недоступные гильдии, ивенты и магазин до его интеграции.
- Title: одно рабочее название, начать/продолжить и подтверждённая замена профиля. Основная кнопка не обязана занимать всю ширину.
- Inventory: сетка не сжимается при выборе. Детали и сравнение в отдельной панели с независимым scroll; Back закрывает её первым. Длинное название переносится по словам. Уже надетый предмет не складывает свои модификаторы повторно в preview.
- После пересборки списка старые Control могут быть освобождены, а новые не должны попадать в Tab-порядок под modal. Используй ModalFocus и проверяй release/restore после нескольких кадров, не только в одном синхронном вызове.
- Reward: сравнение и короткие «Надеть / Забрать», один claim, возврат в World; не гони пользователя через Inventory после каждого боя.
- Checkpoint: короткая шапка, правила под `i`, выбранная точка и **точная цена/потери до подтверждения**. Расход выбранной и последующих точек, fallback +2 и принудительный Лиорен при 3/3 нельзя спрятать. Удаление с подтверждением; смерть нельзя обойти через Back.

### Tall screens / safe area

- Сейчас integer viewport 180×320 сохраняет letterbox на 390×844 и 412×915. Не называй это полноценной адаптацией.
- Сделай отдельный сравнимый эксперимент aspect policy. UI может использовать дополнительную высоту, но спрайты/портреты не должны растягиваться или получать дробную сетку. Потребность в SubViewport докажи конкретным разделением world/UI, не вводи второй runtime без необходимости.
- Реальные screen↔viewport transforms уже используются в SafeArea; не заменяй их отношениями ширины и высоты, теряющими letterbox offset.
- Проверь native Android Back, системные жесты, восстановление после сворачивания. Desktop ui_cancel не является доказательством аппаратного Back.

## 5. Магазин — отдельная реализация

Торговля предусмотрена сюжетом, но runtime ещё не содержит shop scene / wallet / trade service. Сначала выпиши конкретные контракты и изолированный preview, затем интегрируй работающее поведение. Не показывай игроку декоративные кнопки покупки без сделки.

**Канон:** лавка Дайдзиро в Лиорене; валюта — астры; 100 медных = 1 серебряная, 100 серебряных = 1 золотая. Мутный ростовой кристалл в DIA_SHOP_001 оценён в 20 серебряных. Это не означает одинаковую цену каждого runtime echo_crystal: сопоставление качества/аспекта сначала запиши как данные и проверь по narrative. Чистый сумрачный сюжетный кристалл нельзя молча продавать обычной кнопкой.

**UI:** шапка «назад / лавка / деньги»; короткие «Купить / Продать»; 3–4 столбца с иконкой и ценой; выбранный предмет открывает сведения/сравнение/количество/итоговую сумму и один CTA. Торговец говорит при входе и событии, не блокирует каталог постоянной репликой. Недоступность объясняется рядом с действием. Не добавлять paywall, premium-валюту, таймеры офферов или монетизацию.

**Домен:** деньги целым числом минимальной единицы; цены и ассортимент отдельно от сцены; один владелец кошелька. Trade-команда проверяет сумму, остаток, количество, предмет и состояние, затем атомарно изменяет деньги/предметы и эмитит результат. UI не выполняет половины сделки по отдельности.

**Сохранения:** versioned DTO, defensive validation и миграция старого профиля. Валюта входит в обычный Checkpoint rollback по канону, не является мета-ресурсом. Проверить повторный tap, частичную неудачу, отрицательные количества, нехватку денег, продажу надетого предмета, защищённый предмет, полный цикл save/load/restore. Не добавлять серверную экономику.

Числовой прайс, стартовый баланс и ассортимент вне канонического примера остаются явно помеченными гипотезами. По возможности используй существующие определения предметов; не придумывай десятки новых предметов ради витрины.

## 6. Порядок работы и приёмка

1. Запусти текущий build и проверки, выпиши 5–10 оставшихся проблем с кадрами. Не объявляй уже исправленные дефекты текущими.
2. Lead UX и Art Director задают одну композицию на экран и численные бюджеты. Сравни 2–3 решения на одном наборе данных, выбери одно.
3. Внеси минимальные изменения компонентов, затем экранов. Сохрани явного владельца состояния и публичные команды; без дополнительных UI-фреймворков и дублирующих autoload.
4. Интегрируй магазин по отдельному контракту, затем сохрани совместимость профилей. Если данные/инструменты отсутствуют, выполни независимые задачи и конкретно назови блокировку; не выдавай fixture за production.
5. Запусти:

```text
godot --headless --path game --import
godot --headless --path game --script res://tests/test_runner.gd
godot --headless --path game --script res://tests/ui_layout_runner.gd
```

Проверяй не только exit code: SCRIPT ERROR может оставить процесс с кодом 0. Нужны отсутствие script_errors/stderr и отсутствие утечек. Дополняй тесты реальными рисками, не зеркальными проверками координат каждого декоративного узла.

6. Runtime с изолированным `--save-path=user://kimi_compact_ui_review.json`. Окна 360×640, 360×800, 390×844, 412×915; фиксируй actual viewport/scale/offset. PNG viewport может не включать внешние поля окна — подпиши это.
7. Сценарии: normal/look/hold/parts/длинная реплика/светлый фон/resume; оба противника, cooldown, урон, победа/смерть; награда, экипировка, материалы, фильтр; 3 точки, удаление, fallback, 3 Следа; торговля и повторная загрузка. Проверяй tap, pointer emulation, отпускание, drag, focus и Back.
8. Обнови `PROGRESS.md`, `game/README.md`, аудит/решения и новый каталог кадров. Старые доказательства не перезаписывай.

**Готово**, когда изменения есть в игре, сцены читаются и выглядят как единая RPG, действие находится без абзаца инструкции, UI не отнимает центр боя, данные/сохранение не ломаются, а заявленные проверки воспроизводимы. Физический Android, который не запускался, всегда отмечается «не проверено».

Финальный отчёт: что изменилось, какие файлы, кадры до/после, результаты команд и runtime-сценариев, оставшиеся ограничения. Не ограничивайся ещё одним планом вместо реализации.
