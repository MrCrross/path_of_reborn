# Материалы приёмки 20.11.2026

[Аудит и план](../../design/PLAN_ACCEPTANCE_AUDIT_2026_11_20.md). Снято в Godot 4.7.2 на Windows. Живое окно 360×640, logical 180×320, управляемое пошаговое время. Разрешение скриншота совпадает с игровым окном. Геометрию других размеров проверял штатный headless-раннер. Устройства Android в этой приёмке не использовал.

| [Путь после двух побед](acceptance_route_end.png) · [состояние](acceptance_route_end.json) | Один и тот же список открывается двумя кнопками. Вторичная плашка закрывает ноги. Журнал двух побед совпадает в памяти и на диске. |

Живой прогон делал через Godot MCP с отдельным `--save-path=user://iteration_acceptance_20261120_isolated.json`. Первый результат на слизи получил последовательностью `ScreenTouch(index=0, x=15, y=70, press) → move(150,70) → release(150,70)` без эмулированной мыши. Свайп собрал предмет. На втором результате нажал мышью по свободной сцене. В обоих случаях лог показал `Cannot call method 'set_input_as_handled' on a null value` в `combat_screen.gd:137` после перехода. Признак окончания прогона в инструменте — штатная команда остановки управляемого процесса.

[Диагностический скрипт](../../../game/tests/iteration_acceptance_probe.gd) запускается отдельным процессом. Команда текущей версии:

```powershell
godot --headless --path game --fixed-fps 60 --script res://tests/iteration_acceptance_probe.gd -- --save-path=user://por_acceptance_probe_boot_isolated.json
```

Скрипт воспроизводит дефекты, использует уникальный диагностический профиль для теста записи и выводит строку `AUDIT_PROBE_JSON` в stdout. Он рассчитан на состояние проекта на дату аудита. Ошибка `pending_battle_result` на строке 206 в legacy-проверке ожидаема для этой версии. Exit 0 означает завершение сбора наблюдений. Показывать штатной приёмкой следует `test_runner`, `ui_layout_runner`, `animation_assets_runner` и регрессии реализации после исправления. Архивный `probe.json` сохраняет результаты этой итерации.
