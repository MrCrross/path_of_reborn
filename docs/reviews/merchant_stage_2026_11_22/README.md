# Дайдзиро и первая торговля · 22 ноября 2026

Снимок первого прохода. [Повторный аудит и актуальные кадры](reaudit/README.md).

Реализация [плана этапа](../../design/MVP_MERCHANT_PLAN.md): после спасения у телеги Харуто едет в Лиорен, проходит ворота, продаёт кристалл, покупает Куртку странника и может надеть её через «Сумку». Повторный вход открывает торговлю сразу. Следующая сюжетная цель — Гильдия (отдельный этап).

Это проверенный технический и визуальный проход, а не полная приёмка: playtest нового игрока и физический Android остаются открытыми.

## Границы

- Godot `4.7.2.stable.steam`, Windows, Compatibility. Acceptance-прогон — оконный, изолированный профиль `--save-path`.
- Цены первого прогона: Кристалл Эха — 2 000 медных астр (20 сер.), Куртка странника — 1 200 медных астр (12 сер., «станет 8 сер.»). Эффект куртки — +1 к защите, слот «Доспех».
- Торговля у телеги полностью переехала в лавку; телега осталась сюжетной (подарок меча).
- Сюжетного «чистого сумрачного кристалла» в данных нет — реплика об его оценке в диалоге не используется.

## Что изменено

### Маршрут и мир

- После выдачи меча на Тропе появляется действие «В Лиорен»; в Лиорене — «На Тропу» и «В лавку». Значок торговца в нижней навигации в городе ведёт в лавку.
- Сцена ворот (DIA_CITY_001–006) играет оверлеем `DialogueOverlay` при первом въезде с выданным мечом; финальная команда диалога открывает доступ к лавке. Диалог запускается только в Лиорене — на Тропе он не блокирует переезд (исправлено по регрессии acceptance-прогона).
- Лиорен — безопасная зона: свободное касание по городу не начинает бой; отдых при Следах и возврат на Тропу сохранены. Вынужденный переход в Лиорен из-за 3/3 Следов до знакомства не закрывает игрока в тупик.

### Лавка «Сверчок и Сумрак»

- Новый экран `shop.tscn`: вкладки «Купить»/«Продать», строки с иконкой, названием, ценой за единицу и количеством в рюкзаке, состояния «Нет кристаллов для продажи» и «Куплено», обучающие подсказки у нужной вкладки, «Поговорить с Дайдзиро» (DIA_SHOP_008–014) и «Открыть Сумку» после покупки.
- Карточка сделки: эффект экипировки через `EquipmentModel` (дельты замены), количество −/+ для стопок, «Итого / станет» по живым данным, причина недоступности рядом с кнопкой, одно действие «Купить»/«Продать».
- Компоновка шапки: стрелка ‹ слева, название в расширяющемся слоте (перенос в две строки при необходимости), баланс со значком астры справа. Строки списка двухстрочные (название / цена). Это следствие найденной регрессии: системный fallback-шрифт даёт разную метрику от запуска к запуску (название мерилось 110–127 px), поэтому шапка и строки не должны зависеть от измеренной ширины текста — иначе длинная строка продажи раздувала цепочку контейнеров до 190 px и выталкивала баланс за 180 px.

### Домен и сохранение

- `GameSession.travel_to()` — переезд между открытыми точками без отмены канала Печати. `shop_catalog()`/`shop_offers()` — каталог из `game/data/shop/cricket_twilight.json` (куртка 1 200, лимит 1, одноразовый флаг предложения). `buy_item()`/`sell_item()` — одна транзакция с вехами первой продажи/покупки и `last_deal`.
- `GameRoot.commit_shop_deal()` — кандидат → атомарная запись → публикация `deal_committed` в текущий экран без re-navigation; при ошибке записи `deal_rejected` оставляет те же числа для повтора. Двойное подтверждение закрыто guard'ами на экране и в корне.
- Вехи этапа — флаги `world_flags` (`lioren_shop_unlocked`, `shop_intro_done`, `shop_first_sale_done`, `shop_first_purchase_done`, `shop_purchase_briefing_done`, `wanderer_jacket_purchased`): откатываются Печатью вместе с деньгами и инвентарём; `seen_cue_ids` для гейминга не используется.
- Экипировка из «Сумки» закрывает карточку штатным Back, возврат — в городской режим Лиорена с восстановлением фокуса.

### Арт и нарратив

- Runtime-копии по манифесту: ENV-11 (интерьер лавки), CHR-07 (Дайдзиро), ITM-04 (иконка куртки) — через `tools/copy_art.py`.
- Новые диалоги в `game/data/narrative/`: `lioren_gates.json`, `shop_intro.json` (оценка DIA_SHOP_001–007, финальное действие «Оценить кристалл»), `shop_talk.json`, `shop_purchase.json` (брифинг о Гильдии). Диалоги играют оверлеями поверх существующих экранов; `DialogueOverlay` вынесен общим компонентом (используется также у телеги и ворот).

## Android (эмулятор anixart-api35, 23 ноября)

APK собран из того же коммита: debug-экспорт по новому пресету `Android` (`game/export_presets.cfg`, arm64-v8a + x86_64, подпись debug-keystore из editor settings). Шаблоны 4.7.2, build-tools 36.0.0. Два обязательных изменения настройек проекта, без которых экспорт/запуск не работают: `rendering/textures/vram_compression/import_etc2_astc=true` (требование Android-экспорта) и `display/window/handheld/orientation=1` (в Godot 4.7 ориентация манифеста берётся из настройки проекта, поле пресета `screen/orientation` игнорируется — иначе игра стартует в landscape).

Прогон на эмуляторе Pixel 6 (API 35, x86_64, 1080×2400, жестовая навигация), чистая установка, сенсорный ввод через adb tap. [Отобранные кадры прогона](android_merchant_flow.png)

Проверено по штатному пути нового игрока: Title → пропуск пролога → бой со слизью → лут (Кристалл Эха ×2) → телега, разведчик, подарок меча («Надеть») → «В Лиорен» → ворота → оценка → вкладка «Продать» с подсказкой → карточка «Итого: 20 сер. · станет 20 сер.» → частичная продажа (стопка ×2 → ×1, баланс 2K) → вкладка «Купить», карточка «Защита +1, Итого: 12 сер. · станет 8 сер.» → покупка (баланс 800, «Куплено») → «Открыть Сумку · надеть куртку» → карточка «Надето» → возврат в город. Повторный вход: приветствие «Снова ты», торговля доступна сразу. Android Back на корне города выходит в лаунчер; повторный запуск → «Продолжить» → состояние полностью восстановлено (Лиорен, 800 астр, куртка и меч надеты). Вырез на эмуляторе не эмулировался; safe area в кадрах читается по системным панелям (статус/жесты не перекрывают HUD).

Найдено по итогам прогона:

- **«Поговорить с Дайдзиро» не отвечает на касания** в состоянии повторного визита (два промаха подряд, кнопка визуально на месте). Торговля при этом работает. Требует проверки на десктопе: фокус/обработчик кнопки.
- **Слой экипированного оружия (уже закрыто в дереве):** в собранном APK спрайт мира всё ещё показывал базовую стойку с деревянной палкой, а надетый меч рисовался поверх другой руки. В текущем дереве выбор стойки на экране мира зависит от слота оружия (`ArtMap.hero_still_id`: ветка / тренировочный меч / без оружия), поэтому артефакт должен исчезнуть при пересборке APK; при следующем Android-прогоне стоит снять контрольный кадр.

## Открытая приёмка

- **Физическое устройство не проверено:** прогон выполнен на эмуляторе (touch жесты через adb, без выреза и реальных сенсоров). Вырез, настоящий touch, жизненный цикл на железе и производительность остаются открытыми; инфраструктура экспорта (пресет, шаблоны, keystore) готова.
- **Playtest нового игрока по протоколу не зафиксирован:** наблюдения эмуляторного прогона (лавка находится по подсказке после ворот, вкладки различимы, покупка проходит без подсказок) — не замена живому прогону.
- Замечания о разговоре и стойке с оружием относятся к APK от 23 ноября. В текущем дереве разговор и возврат фокуса прошли оконную проверку, стойки проверены по анимационным контрактам. [Аудит MVP](../mvp_audit_2026_11_26/README.md)
- **Гильдия — следующий сюжетный этап:** регистрация и связанные реплики (DIA_CITY_007+) не входили в этот план.
- Метрика системного fallback-шрифта плавает между запусками (наблюдалось 110–127 px для одной строки). Компоновка шапки и строк лавки от этого защищена; другие экраны с длинными подписями при приёмке стоит перепроверять на широкой метрике.
