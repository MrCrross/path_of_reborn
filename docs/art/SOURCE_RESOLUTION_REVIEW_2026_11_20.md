# Полноразмерные исходники — проверка в Godot

Продолжение: позднее в этот же день [15 анимационных клипов реализованы и подключены](ANIMATION_UPGRADE_REVIEW_2026_11_20.md). Ниже сохранён исторический результат отдельного proof; его проблемный raw idle не использован в новой версии. Три отдельных still-кандидата и лесной фон не считаются автоматически заменёнными этим этапом анимаций.

20 ноября 2026. По вопросу пользователя проверено, можно ли использовать большие оригиналы, из которых ранее делались маленькие ассеты. **Да: отдельные полноразмерные PNG уже работают в Godot с сохранением деталей и прежних игровых пропорций.**

Исходники найдены по assets/manifest.json; новая генерация не потребовалась. Для передачи подготовлены исходный фон и crop-версии спрайтов с неизменными оставшимися RGBA-пикселями. Палитра, размер пикселя и alpha не упрощались. Размер на экране задавался трансформом в отдельной Godot-сцене. В основном game/ и production assets изменений нет.

Текущий проект уже использует `canvas_items`, который рисует непосредственно в целевом разрешении окна; размер дизайна не равен обязательному разрешению всех текстур. Это соответствует [документации Godot о нескольких разрешениях](https://docs.godotengine.org/en/stable/tutorials/rendering/multiple_resolutions.html). Перестраивать базу координат UI ради одного только сохранения текстур необязательно. При маленьком физическом размере персонажа часть деталей всё равно не поместится в экранные пиксели.

Выполнены 9 GPU-рендеров: current/source в 360×640, 720×1280 и 1080×1920; один linear diagnostic и два source idle. 1080×1920 получены в настоящем GPU SubViewport: desktop ограничивает размер окна. Это не Android-проверка и не upscale готового маленького скриншота. Просмотрены сравнение малого экрана, большой рендер, hero crop, оба idle и alpha на светлом/тёмном фоне. Увеличение сохраняет лицо, галстук, одежду и прут. PNG-кандидаты технически пригодны для следующего review, но не получили production approval.

У raw idle высоты solid silhouette 612/635 px: при общем масштабе есть дрейф примерно 2,97 логического px. Прут на этих кадрах не читается, поза/плащ меняются. Большие листы нельзя заменить автоматически; нужны регистрация кадров и cleanup. Старый pixel-grid proof остаётся отдельным сравнением. Для source-resolution семейства строгая общая сетка ещё не подтверждена.

Расчёт памяти трёх crop/native still-текстур RGBA8 — 16,32 MiB без mipmaps, накладных расходов и остальных ресурсов. Это арифметика, не результат GPU-профилирования. Nearest остаётся основным фильтром. Системные сообщения о недоступных shader cache/user:// и certificate store сохранены в логах; ошибок скрипта/записи снимков в итоговых прогонах нет. Android, FPS, HUD-контраст и экспорт не проверены.
