# REFERENCE COLLECTION PLAN

Цель — получить проверяемое понимание UX-паттернов Path of Kings и преобразовать его в оригинальные wireframes Path of Reborn. Референсы не импортируются в production.

## Этап 1. Поиск

**Вход:** название, package id `com.TornadoBear.WayofKings`, текущая дата и официальная страница.

**Действия:** открыть Google Play и страницу издателя; найти официальный trailer; искать записи gameplay по точному названию и разработчику; отделять пользовательские материалы от официальных; фиксировать дату, URL и версию приложения. Проверять, что экран содержит узнаваемый UI/игровой момент, а не рекламу другой игры.

**Результат:** таблица источников с типом, URL, статусом и ограничениями. **Приоритет P0.**

**Критерий завершения:** есть официальный store page, минимум один официальный визуальный материал и отдельный список вторичных материалов с пометкой «не первичный источник».

**Блокеры:** региональная недоступность, удалённое видео, динамические изображения без загрузки, отсутствие доступа к устройству.

## Этап 2. Сбор

**Вход:** список источников.

**Действия и приоритеты:**

- **P0:** основной экран во время боя, размещение HP/ресурса/кнопок, победа/поражение, экран добычи или экипировки;
- **P1:** карта/переход между локациями, карточка предмета, развитие героя, модальное окно улучшения;
- **P2:** магазин, события, социальные функции, будущие режимы.

Получать материалы через разрешённое сохранение из store/trailer или ручной capture собственного установленного приложения. Не обходить DRM и не использовать скачанные копии в игре.

**Результат:** оригинальные ссылки и, если правила источника позволяют, файлы в `references/path-of-kings/` с понятным именем. Пять официальных Google Play screenshots скачаны 17.11.2026; trailer пока представлен только ссылкой на thumbnail.

**Критерий:** для каждого P0 экрана есть изображение или явная запись «не доступно, получить вручную». Локальные изображения остаются reference-only и не импортируются в игру.

## Этап 3. Каталогизация

Имена файлов: `poki_<screen>_<source>_<yyyy-mm-dd>.<ext>`, например `poki_combat_googleplay_2026-11-17.jpg`. В каталоге хранить ID, тип, оригинальный URL, локальный путь, дату получения, описание, изучаемые элементы, планируемые изменения и статус проверки.

**Результат:** обновлённый `REFERENCE_CATALOG.md`. **Критерий:** внешний наблюдатель может открыть источник и понять происхождение каждого материала.

## Этап 4. Анализ

Для каждого экрана записать orientation, aspect ratio, safe areas, относительные зоны в процентах, размер главного фокуса, порядок внимания, touch targets, путь входа/выхода, частоту одно-ручного доступа и видимые состояния ошибки/награды. Разделять наблюдение, интерпретацию и гипотезу. До ручного просмотра официальных изображений не фиксировать pixel-level выводы.

**Результат:** таблица UX-анализов и список паттернов, которые можно перенести только на уровне поведения. **P0/P1.**

## Этап 5. Собственный UI

На основе только обобщённых паттернов нарисовать чёрно-белые wireframes Path of Reborn в portrait 9:16. Проверить главный фокус, thumb reachability, контраст, overflow и состояния empty/loading/error. Заменить цвета, формы, тексты и композиционные решения на оригинальные.

**Критерий:** P0-потоки проходят без референсных изображений и без неоднозначных кнопок.

## Этап 6. Asset preparation

Из wireframes составить Asset Brief для каждой иконки, рамки, фона, героя, монстра и эффекта. Применять шаблоны из `docs/art/ASSET_PROMPT_TEMPLATES.md`; сохранять prompt и версии; провести нормализацию пикселей до импорта.

## Этап 7. Проверка готовности

До программирования прототипа должны быть: подтверждённый portrait target, wireframes P0, утверждённый MVP, правила Checkpoint v0, список production assets, palette test, импортный smoke test и список открытых вопросов. Блокирующие проблемы фиксируются в issue/документе, а не замалчиваются.
